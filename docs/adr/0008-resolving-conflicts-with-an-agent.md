# Resolving merge conflicts with an Agent

A Merge that conflicts aborts and names the files. That kept the Project safe, but it sent the user back to a terminal for exactly the work an Agent is good at: reading two sides of a change and reconciling them. **Resolve** closes that gap without giving up the abort. The user is offered "Resolve with an agent" on the conflict, which Spawns a **Resolver**; when it finishes, the app completes the Merge and both Agents land in Delivered.

The Resolver's branch is **cut from the conflicted Agent's branch**, and it merges the target into *that*. This is the ordinary "bring my branch up to date" move, done in a Worktree of its own: the Project is never half-merged, so ADR 0004's reason for aborting still holds; and the conflicted Agent's branch is never written to, so its record of what it did stays intact. The resolution then reaches the target as a plain `--no-ff` Merge of the Resolver's branch, which now contains the target and so applies cleanly. It is not the Agent-into-Agent merge ADR 0004 defers — nothing is merged *into* an Agent's branch; one is used as a starting point.

The app **finishes the Merge itself** when the Resolver's Turn Completes. That is a write to the Project no click directly preceded, which ADR 0004 reserved for the user. The user's click on Merge, and then on Resolve, is the request; the Resolver is how it gets fulfilled, and making them click Merge a third time would only add a step that can't mean anything different. The finish is guarded so it cannot merge something unexpected: the target must already be in the Resolver's branch (it did merge it), its Worktree must be clean, and `git merge` must apply without conflict. Any refusal leaves the Resolver Completed with a line in its transcript saying why; the user can reply to it or Merge it by hand. It happens once — after its Merge goes through, a Resumed Resolver is an ordinary Agent.

Both Agents are **recorded as Merged**, which is all Delivered needs (ADR 0007). The conflicted Agent is recorded only if its branch tip is in the target afterwards, so one that was Resumed and committed while the Resolver worked is not filed under Delivered with work the Project has not got. Manually Merging a Resolver records the conflicted Agent the same way.

The Resolver's **Base is the target's tip**, not the conflicted Agent's, so its diff shows what the finished Merge will bring into the target rather than the whole of the target's history since the Agent was cut. It **always runs YOLO**: a plan-mode Resolver could not write the resolution. Model and effort are whatever the next Spawn would use.

A conflict is now **an outcome of `agent_merge`**, not an error: the UI needs the target and the file list to offer Resolve, and a string it would have to parse is the wrong way to hand them over.

Considered and rejected: **resolving in place in the Project**, which is the half-merged state ADR 0004 refuses. **Resuming the conflicted Agent** with a "now merge `main`" prompt, which is cheaper but writes a merge into the branch the user is reading as that Agent's work, and puts it back to Running when the user asked for a second pair of hands. **Rebasing** the Agent's branch onto the target, which rewrites its commits — the thing ADR 0004 chose `--no-ff` to avoid. **Leaving the final Merge to the user**, covered above.

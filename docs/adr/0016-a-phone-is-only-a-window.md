# A phone is only a window

The app runs on an iPhone as the same Tauri app, with the same webview and the same Rust window code. It doesn't run as a separate client. A phone can't be a Host: iOS won't let an app start `claude`, or `git`, or any other process, so it can't run Agents. So the app there is **a window with no Host of its own**. It reaches the Hosts the user adds by Tailscale name, over the tailnet, exactly as a desktop window reaches another machine's (ADR 0012). The Tailscale app on the phone puts it on the tailnet as the user's own identity, which is all the Hosts check.

Most of the window doesn't care which machine it is on, because everything it shows already comes from a Host. What changes is everything that assumed there is always a Host on this machine. The Rust side builds no local Host link on a phone. The UI learns before its first frame that it's on one (`window.__MOBILE__`, read in `platform.ts`), and `hosts.own` is then null. With no Host of its own, the window waits for none at startup. It asks whichever Host it can reach for things that are the same everywhere, like the model list. Its "+" adds a machine, since it has no folders of its own to add as Projects. On a phone, a Host being offline is only worth a banner when none of them can be reached, which usually means Tailscale is off. On a phone-sized screen the window shows one thing at a time: the project list, or the agent opened from it, with a back button and the edge swipe iOS users expect. A tablet keeps the desktop's side-by-side panes.

The iOS build is made, signed and sent to TestFlight by CI on GitHub's macOS runner (`.github/workflows/ios.yml`), because nobody working on the app has a Mac. For the same reason the Xcode project isn't committed. CI generates it from `tauri.conf.json` on every build, and the Info.plist additions live in `src-tauri/Info.ios.plist`, which Tauri merges in. Signing uses an App Store Connect API key, so Xcode makes the certificate and profile itself, and the same key uploads the build.

**Consequences.** A Turn finishing can only notify the phone while the app is open: iOS suspends a backgrounded app and drops its connections. Notifications on a locked phone need the Hosts to send push notifications through Apple, which is its own decision. Without a Mac there is no Simulator either, so each iOS check is a CI run plus TestFlight processing. The parts that aren't specific to iOS can be tried on Android, which builds on Linux.

Considered and rejected: a separate phone client (two UIs to keep in step for one set of Hosts), and a Host-served web page (it would need its own authentication, and a page can't be a Tailscale peer the way an app on the phone can).

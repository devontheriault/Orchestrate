# Resumable Agents via `claude --resume`

An Agent used to be one `claude` process running one prompt: when the process exited the conversation was over, and the only way to say anything more was to Spawn a new Agent against a fresh Worktree. That is the wrong shape for real work — most tasks need a correction or a follow-up, and starting over throws away both the Worktree's state and everything Claude Code had figured out.

Agents are now **conversations made of Turns**. Each Turn is one `claude --print` process; Turn 1 carries the Task, and Resume starts another Turn in the *same* Worktree with `--resume <session>`. Claude Code keeps the transcript; we keep only the Session ID. This follows the "prefer existing Claude Code capabilities" principle — resumption already exists in the CLI, so there is no conversation store or agent loop here to maintain.

We **mint the Session ID ourselves** at Spawn and pass it as `--session-id <uuid>`, rather than reading it off the first `init` event. An Agent is then resumable from the instant it starts, including one that dies before emitting a line — which is exactly the Failed and Orphaned case a user most wants to pick back up. The stream is still watched for a `session_id`, and a different one overrides ours, so a CLI version that forks or renames sessions stays resumable.

The consequence worth naming: **Stop no longer Discards.** It used to terminate the process and delete the Worktree in one action, which is untenable once Agents are conversational — the main reason to Stop is to interrupt an Agent going the wrong way and Resume it with a correction, and that requires its Worktree and Session to survive. Stop now only ends the current Turn, and Discard is the single explicit action that destroys anything. The cost is that a Stopped Agent leaves a Worktree behind until the user Discards it, so Discard sits in the same place the Stop button was. It is now the only destructive action in the app, and it takes two clicks to fire.

A Session is scoped by Claude Code to the directory it ran in, so it lives and dies with the Agent's Worktree. That is why Resume is refused once a Worktree is gone, and why Discard is documented as taking the Session with it. Agents recorded before this change have no Session and cannot be Resumed; the composer says so rather than failing on send.

Considered and rejected: `--fork-session` on every Resume (a new ID per Turn buys nothing here and costs us a stable handle), and `--continue` instead of an explicit ID ("most recent conversation in this directory" is implicit state we'd rather not depend on, even though one Worktree holds one Session today). Also rejected: queueing a follow-up typed while an Agent is still working. Sending it as a second concurrent `claude` in one Worktree would have two processes writing the same files, and holding it to send later hides a pending action in the UI — so the composer is disabled while a Turn runs, and the user Stops to change course.

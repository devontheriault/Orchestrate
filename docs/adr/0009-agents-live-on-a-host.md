# Agents live on a Host, not in the window

Until now every Agent was a child of the app's window process: closing the window stopped the runtime, and anything mid-Turn became an Orphan. That rules out the thing the app is now for — Agents that keep working on the most powerful machine while the user is on another one, or away entirely. So the runtime moves out of the window into a **Host**: a long-lived process, one per machine, installed as a user service and started at login, that owns every Agent's `claude` processes, Worktrees, Sessions, logs and Queue. The window becomes a client of any Host it can reach, its own machine's included.

**Every window goes through a Host, even on one machine.** Keeping the in-process runtime for the local case would mean two paths through every action, and the local path would still kill Agents on close. With one path, closing the window never Orphans anything; an Orphan is now an Agent whose *Host* stopped.

ADR 0001 rejected the Agent SDK partly because it forced "a sidecar architecture and IPC boundary". That objection was to paying for a boundary to gain nothing Rust couldn't already do; here the boundary is the feature. The Host is still Rust, still drives `claude --print --output-format stream-json`, and `src/lib/api.ts` is still the one place the UI crosses it — only now over a WebSocket rather than Tauri IPC. The protocol is kept free of anything Tauri-specific, so a phone or browser client can speak it later.

Starting, stopping and "keep running when I'm logged out" differ by operating system, so they sit behind one small per-OS module (install, uninstall, start, stop, status, keep-running). V1 implements it for systemd only, since every machine in use runs Linux. Other platforms are an implementation of that module, not a redesign — though on macOS and Windows, running while logged out needs a system-level service rather than a per-user one, and Claude Code's macOS credentials sit in a Keychain that is locked while no one is logged in.

**Consequences.** An update restarts the Host, which would Orphan running Turns, so an unattended update waits until no Turn is running. A window and a Host on different versions refuse to talk, and the window says which one to update, rather than half-working across a changed protocol. Agents and Queues from before the Host existed are taken over by the local Host on first run.

# One theme file

Every visual decision in the app — colour, type, spacing, radii, shadow, motion, and the look of a button or an input — now lives in `src/lib/theme.css`, imported once from `src/routes/+layout.svelte`. Before this, the root layout held fifteen colour tokens and a handful of layout measurements, and everything else was written inline: 23 distinct `font-size` values across 20 components, 14 radii, and 62 raw colour literals written outside the layout's token block, including three components carrying their own `prefers-color-scheme: dark` block. Changing the app's accent meant a grep; changing its type scale meant reading every component to work out which sizes were the same idea spelled differently.

Tokens are named for the **job, not the hue** — `--accent`, `--danger`, `--diff-add-fg` — so one edit retints the app rather than lying about what it is. Where a status and a semantic colour are the same thing today, the status is an **alias** (`--running: var(--success)`, `--attention: var(--warning-text)`) rather than a second copy of the value; the two can diverge later without either drifting by accident.

Type collapsed onto a **nine-step scale**, `--text-3xs` through `--text-3xl`, with `--text-md` as the body size. The 23 old values clustered tightly — 0.82, 0.83, 0.84, 0.85 and 0.86rem were all the same intent — so each mapped to its nearest step. Most moved under 3%; the largest shifts were 1.2rem and 1.1rem meeting at `--text-3xl` (1.15rem) and 0.62rem rising to `--text-3xs` (0.65rem), around 4–5%. Rendered-markdown sizes stayed in `em`, because there they are deliberately relative to whatever size the transcript sets rather than absolute.

Dark mode is **the same token names with different values**, all of them in one `prefers-color-scheme` block. The three component-level dark blocks are gone, and the rule that replaces them is: a component never writes its own dark-mode override; if it needs one, the colour it wants is missing a token. Folding those blocks in gave three colours a dark treatment they had never had — the M file badge, `.done.err`, and the failure banner's label were a light-mode red or amber rendered unchanged on a near-black surface — so dark mode is now slightly more legible than before, in exactly the places nobody had got to.

Controls are **global classes**, not just tokens. `theme.css` is a plain stylesheet rather than a Svelte `<style>` block, so the classes are global without `:global()` and a component can put `class="btn btn-primary"` on a button and be done. A component keeps only what makes its control *different* — the commit box's textarea keeps `resize: vertical`, and nothing else. The set is:

- `.btn` with `.btn-primary` / `-danger` / `-warning` / `-ghost` / `-select`, and the `-sm` / `-lg` / `-icon` / `-pill` modifiers.
- `.input` / `.textarea` / `.select`, sharing the button's border, radius and focus ring, plus `.field-label` / `-hint` / `-error`.
- `.popover` for any floating surface, `.menu` for the common case of a list in one, and `.menu-item` / `-tick` / `-label` / `-note` / `-more` / `-sep` for its rows.
- `.status-dot` and `.badge`, both taking their colour from the lifecycle tokens, so a state reads the same in the tree, the sidebar and the header without three copies of the map.

The menus are where this paid the most. The two pickers each hand-rolled an identical trigger, floating list, and row highlight; `ModelPicker` alone lost 90 lines of stylesheet and kept only the three rules that make it different from `BranchPicker` — it is wider, it is the spawn form's main control, and its rows open a submenu. One deliberate omission: `.menu-item` has **no `:hover` rule**. The pickers set `data-active` from `pointermove` so that arrowing through a list does not also light whatever row the resting cursor is over, and a hover rule in the theme would have quietly broken that.

The **space scale** was fitted to the app rather than imposed on it. The existing values clustered hard — 0.4rem sixteen times, 0.5rem nine, 0.35rem five — so the steps were put on those clusters. Snapping every `gap` and every single-value `padding` and `margin` onto `--space-1`…`--space-8` moved the four commonest values not at all, and moved nothing by more than 0.1rem, which at this root size is under a pixel and a half.

The sweep stopped at **single-value** declarations on purpose. A `gap` is layout rhythm and belongs on a scale. A padding like `0.7rem 3rem 0.7rem 0.85rem` exists to keep the composer's text from running under the send button; it is geometry, and rounding it to a scale would be cargo-culting. Control padding keeps its own `--control-pad-*` tokens for the same reason.

**Scrollbars** were the last thing the stylesheet did not reach. Left alone they are the platform's — a wide grey slab on WebKitGTK that reads as a hole in a dark window. They are now thin and dimmed, driven by `--scrollbar-thumb`. The standard `scrollbar-width` / `scrollbar-color` properties and the older `::-webkit-scrollbar` rules are mutually exclusive by design: an engine that understands the standard ones ignores the WebKit ones anyway, so the latter sit behind `@supports not (scrollbar-width: thin)` and exist only for engines that need them. Setting `color-scheme` on the root (see ADR 0006) is what makes the native parts — form controls, the canvas behind the page — follow along.

Considered and rejected: **a two-layer palette**, raw values feeding semantic aliases, which is the usual design-system shape but adds an indirection this app has no second brand to justify. **Tokens without the control classes**, which leaves every component still writing its own button and keeps the duplication the tokens were meant to remove. **A scale of round numbers** for spacing — 4/8/12/16px — which is the conventional answer and which every single value in this app would have had to move to reach. **Sweeping multi-value padding** onto the space scale, covered above. **Migrating every button call site at once**, which would have buried a mechanical refactor in a large behavioural diff; the commit box, the sidebar, the pickers and the flyout were converted, and the rest move over as they are touched.
